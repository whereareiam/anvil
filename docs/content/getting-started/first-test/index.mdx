---
title: First test
description: Start pinned Paper, connect a native player, and verify server presence and a message.
---

This test starts Paper, logs in an offline player called Alice, and verifies that the player receives
a message sent through the server console. It gives you a working environment before adding your
plugin's own assertions.

Complete [installation](../installation/index.md) first. The example uses the pinned Paper build
`1.21.11 / 132`, the Paper platform unit, and MCProtocol support from that setup.

## Create the scenario [step]

Save this as `src/anvil/java/com/example/test/PaperScenario.java`:

```java
package com.example.test;

import me.whereareiam.anvil.api.model.process.Distribution;
import me.whereareiam.anvil.api.model.process.MinecraftServer;
import me.whereareiam.anvil.api.model.scenario.AnvilScenario;
import me.whereareiam.anvil.api.scenario.AnvilScenarioDefinition;
import me.whereareiam.anvil.api.type.Platforms;
import org.jetbrains.annotations.NotNull;

public final class PaperScenario implements AnvilScenarioDefinition {
	@Override
	public @NotNull AnvilScenario define() {
		MinecraftServer server = MinecraftServer.builder()
				.name("server")
				.platform(Platforms.PAPER)
				.distribution(Distribution.remote("1.21.11", "132"))
				.build();

		return AnvilScenario.builder()
				.name("first-paper-test")
				.entrypoint("server")
				.server(server)
				.build();
	}
}
```

`server` identifies the process inside this scenario. Making it the entrypoint tells newly created
players where to connect. The distribution identifies an exact build so repeated runs use the same
server release.

## Write the test [step]

Save this as `src/anvil/java/com/example/test/PlayerJoinTest.java`:

```java
package com.example.test;

import me.whereareiam.anvil.api.scenario.ScenarioContext;
import me.whereareiam.anvil.capability.messages.Messages;
import me.whereareiam.anvil.capability.server.Server;
import me.whereareiam.anvil.capability.session.Session;
import me.whereareiam.anvil.integration.junit.AnvilTest;
import org.junit.jupiter.api.Test;

import static org.junit.jupiter.api.Assertions.assertEquals;
import static org.junit.jupiter.api.Assertions.assertTrue;

class PlayerJoinTest {
	@Test
	@AnvilTest(PaperScenario.class)
	void aliceReceivesTheServerMessage(ScenarioContext anvil) {
		var alice = anvil.players().create("Alice");
		var session = alice.capability(Session.class);
		session.connect();
		session.connected();

		var identity = alice.capability(Server.class).joined("server");
		assertEquals("Alice", identity.getObserved().getUsername());

		anvil.processes().server("server").console()
				.sendCommand("say anvil-first-test");
		String message = alice.capability(Messages.class).received("anvil-first-test");
		assertTrue(message.contains("anvil-first-test"));
	}
}
```

Creating Alice allocates the player; `connect()` starts login. The two waits establish different
facts: `connected()` waits for the protocol session, while `joined("server")` waits for the server
agent to observe Alice. The final assertion checks a message delivered to the client.

## Run and inspect the result [step]

Run from your project root:

```shell
./gradlew anvilTest --tests 'com.example.test.PlayerJoinTest'
```

The first run downloads the pinned runtime artifacts and prepares a workspace. A passing test means
that Paper started, the native player joined, the agent observed its identity, and the client received
the console message. Gradle writes the JUnit report to `build/reports/tests/anvilTest/index.html`.
The extension closes the players and processes at the end of the test.

If a distribution cannot be resolved, check the configured repositories and
[distribution selection](../../building-blocks/environments/provisioning/platform/index.md). If login fails,
check [versions and compatibility](../../building-blocks/environments/platforms/versions/index.md) and the
process diagnostics in [troubleshooting](../../help/troubleshooting/index.md).

## Run the same test on Bedrock Edition [step]

The same test runs against a Bedrock Edition server. Apply the Lumi platform unit and add the
CloudburstMC Protocol library next to the setup from [installation](../installation/index.md):

```kotlin
plugins {
	id("me.whereareiam.anvil.platform.lumi") version "0.0.1"
}

dependencies {
	add("anvilRuntimeOnly", "me.whereareiam.anvil:protocol-cloudburst:0.0.1")
}
```

Save the scenario as `src/anvil/java/com/example/test/LumiScenario.java`:

```java
package com.example.test;

import me.whereareiam.anvil.api.model.process.Distribution;
import me.whereareiam.anvil.api.model.process.MinecraftServer;
import me.whereareiam.anvil.api.model.scenario.AnvilScenario;
import me.whereareiam.anvil.api.scenario.AnvilScenarioDefinition;
import me.whereareiam.anvil.api.type.Platforms;
import org.jetbrains.annotations.NotNull;

public final class LumiScenario implements AnvilScenarioDefinition {
	@Override
	public @NotNull AnvilScenario define() {
		MinecraftServer server = MinecraftServer.builder()
				.name("server")
				.platform(Platforms.LUMI)
				.distribution(Distribution.remote("1.26.50", "1.6.9"))
				.build();

		return AnvilScenario.builder()
				.name("first-lumi-test")
				.protocolLibrary("cloudburst")
				.entrypoint("server")
				.server(server)
				.build();
	}
}
```

The distribution names the Bedrock version, `1.26.50`, and the exact Lumi release that runs it.
`protocolLibrary("cloudburst")` overrides the engine's `mcprotocol` default for this scenario, so its
players speak Bedrock. Copy `PlayerJoinTest` to `BedrockJoinTest` and change only the annotation to
`@AnvilTest(LumiScenario.class)`; the capabilities, the console and the assertions stay the same. Lumi
delivers the console's `say` as an announcement, which Alice receives as
`chat.type.announcement CONSOLE anvil-first-test`, so the `contains` check still holds.

```shell
./gradlew anvilTest --tests 'com.example.test.BedrockJoinTest'
```

A passing run means that Lumi started on a UDP listener, the Bedrock player logged in offline with a
self-signed identity, the Lumi agent observed Alice, and the client received the announcement.
[Lumi](../../building-blocks/environments/platforms/servers/lumi/index.md) lists the versions and settings,
and each [capability page](../../building-blocks/players/capabilities/index.md) notes what a Bedrock player
does differently.
